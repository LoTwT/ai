# 食物热量估算方法

在需要估算或重算食物热量时完整执行本文。不要把最终总热量当成直觉判断；让每个数字都能追溯到食物识别、份量、能量依据与计算分支。

## 核心原则

遵守三条不可违反的规则：

1. **让每个数字都有推导过程。** 不要凭直觉直接给出总热量。
2. **先得到可量化份量，再计算热量。** 固体先估重量，饮品先估容量；只有包装或品牌给出规格明确的整份热量时才直接使用。
3. **对仍无法确认的不确定项取合理高值。**
   - 烹饪方式不确定时，采用修正倍数较高的合理档位；
   - 份量不确定时，采用合理范围内偏高的值；
   - 食物品种不确定且不需要追问时，采用同类中热量较高的值；
   - 饮品糖度不确定时，按全糖计算；
   - 饮品高热量加料不确定时，先追问；
   - 杯型不确定时，按大杯计算。

### 数据获取优先级

不要在本方法中硬编码具体菜品的热量映射。容器尺寸、食物密度、可食比例、饮品组件等结构性估算常量可以固定；具体食物的能量值按以下顺序取得：

1. **已验证的个人食物热量索引**：先查 `food-calorie-index.md`。同一或高度相似食物且规格一致时，直接使用其每 100g、每 100ml 或整份 SKU 数据。
2. **包装营养标签**：照片中清晰可读时直接使用。
3. **品牌官方数据**：识别到品牌、产品名与规格时，查询品牌官方数据。
4. **可靠的成品数据**：优先查定义清楚的成品每 100g 或每 100ml 数据。
5. **训练知识**：使用中国食物成分表、USDA 等知识，并按下方规则决定是否交叉验证。
6. **Web 搜索**：前述来源不确定时搜索并交叉验证。
7. **原料拆解**：只有找不到可靠成品数据时，才拆为原料并使用一次烹饪修正。

取得索引未收录的数据后，只把可复用且来源可靠的成品能量密度或明确品牌 SKU 写入 `food-calorie-index.md`。不要把低置信度照片推断、标准份量兜底或原料拆解结果自动升级为永久基准；同一标准化键只更新一条。

### 交叉验证规则

训练知识给出的数据若属于高热量食物（超过 200 kcal/100g）或不常见食物，主动搜索一次验证。搜索结果与训练知识偏差超过 20% 时，采用合理高值并标明不确定。

## 第一阶段：食物识别

### 处理多张图片

先判断多张图片是否为同一组食物的不同角度：

- 同一容器、摆放和食物组合只计算一次；选择信息最丰富的照片为主，其他照片补充品牌、份量或遮挡细节。
- 不同容器或不同食物分别识别。
- 无法判断是否重复且可能显著改变热量时，先向用户确认。

### 扫描顺序

先执行品牌预判，再按固定顺序扫描，避免遗漏：

**品牌预判**：快速查找 logo、杯贴、包装文字、产品名、口味、容量和营养标签。发现明确品牌时，先为该项目执行“连锁品牌快捷路径”，再继续扫描其余食物。

1. **主食**：米饭、面、馒头、饼、年糕等，通常体积最大、颜色较浅；
2. **蛋白质主菜**：肉、鱼、蛋、豆制品等；
3. **蔬菜或配菜**：绿色或彩色部分；
4. **汤类**：辨认汤水和固体配料；
5. **饮品**：牛奶盒、咖啡杯、瓶罐、奶茶杯等；
6. **零食或包装食品**：独立包装物；
7. **明确可见的蘸料**：只处理照片中出现的蘸碟。

### 形成识别记录

每识别一项食物，先在内部形成：

```text
(食物名称, 烹饪方式, 识别依据, 置信度)
```

食物名称、烹饪方式或识别依据无法确定时，执行追问决策矩阵。水果、包装食品等没有烹饪方式的项目填 `N/A`。

### 识别关键点

**看文字**：优先读取包装上的品牌名、品名、口味、容量、定制选项和营养标签。饮品杯贴通常包含名称、杯型、甜度和加料。

**看烹饪方式**：根据外观判断：

- 表面油亮、有焦痕：倾向煎、炸或炒；
- 颜色清淡、有汤水：倾向蒸、煮、烫或炖；
- 深色酱汁裹覆：倾向红烧、卤或酱；
- 表面干燥、有烤痕：倾向烤或烘。

### 追问决策矩阵

按热量影响决定是否打断用户，并把必须确认的问题尽量一次问完：

| 情况 | 可能影响 | 行为 |
|---|---|---|
| 肉类主要品种不确定（猪、牛、鸡、鸭） | 可达约 2 倍 | **必须问** |
| 烹饪方式不确定（如炒与炸） | 可达约 1.5 倍 | **必须问** |
| 饮品高热量加料不确定（珍珠、奶盖等） | 可达约 2 倍 | **必须问** |
| 份量大小不确定 | 取决于偏差 | 可能偏差超过 30% 时**必须问** |
| 饮品糖度不确定 | 约 20% | 不问，按全糖计算 |
| 杯型不确定 | 显著但可保守兜底 | 不问，按大杯计算 |
| 蔬菜品种不确定 | 通常小于 10% | 不问，采用同类合理高值 |
| 调味咸淡不确定 | 几乎无热量差异 | 不问 |

图片完全无法辨认时，请用户补充描述；可以大致判断时采用合理高值，并将该项标为低置信度。

### 连锁品牌快捷路径

识别到品牌 logo、包装或杯贴时：

1. 确认品牌和具体产品名；
2. 确认杯型、容量、口味和版本等关键规格；
3. 查询品牌官方公布的热量；
4. 找到且规格一致时，直接使用品牌 SKU 的整份数据；
5. 找不到或规格无法确认时，回到常规估算流程，并对仍不确定的项采用合理高值。

## 第二阶段：份量估算

固体食物不要跳过重量直接给热量；饮品先估容量，再按 ml 流程计算。包装或品牌给出精确整份热量时，仍记录其份量语义，但可直接使用整份热量。

按以下优先级确定数量，并在记录中使用相应的 `quantity.method`：

1. 包装净含量（`package`）或品牌明确规格（`brand_spec`）；
2. 用户明确提供的数量（`user_provided`）；
3. 可数食物的数量法（`count`）；
4. 容器容量、填充比例和食物密度（`container`）；
5. 已知尺寸食物或物体作为锚点（`anchor`）；
6. 同类历史份量比例（`history_ratio`）；
7. 标准份量兜底（`standard_portion`）。

当表格给出范围而照片无法进一步收窄时，采用范围上限。

### 第一级：容器锚定

容器通常是最可靠的尺寸参照：

1. 判断容器类型；
2. 对碗或盒，使用 `容量 × 填充比例 × 食物密度` 估算重量；
3. 对平盘，使用 `覆盖面积 × 平均厚度 × 食物密度` 估算重量。

#### 家用餐具参照

| 容器 | 口径 | 容量 | 识别特征 |
|---|---|---|---|
| 标准饭碗 | 11-12cm | 300-400ml | 最常见，单手可握 |
| 大饭碗或汤碗 | 15-18cm | 600-800ml | 通常需要双手端 |
| 小碟 | 10-12cm | — | 酱料或小菜 |
| 家常菜盘 | 20-23cm | 面积约 300-400cm² | 圆形平盘 |
| 大盘 | 25-30cm | 面积约 500-700cm² | 多人菜 |

#### 外卖容器参照

| 容器 | 尺寸 | 容量 | 识别特征 |
|---|---|---|---|
| 小圆盒 | 口径 12cm | 300-400ml | 米饭或小份菜 |
| 标准方盒 | 15×12cm | 500-650ml | 常见外卖盒 |
| 大方盒 | 18×13cm | 750-1000ml | 大份或双拼 |
| 长方盒（便当） | 22×15cm | 800-1000ml | 分格便当 |
| 圆形汤碗 | 口径 14-16cm | 400-500ml | 带盖 |

#### 餐厅餐具参照

| 容器 | 口径或容量 | 识别特征 |
|---|---|---|
| 米饭小碗 | 10-11cm / 约 250ml | 比家用碗小一号 |
| 面碗 | 18-20cm / 约 800-1000ml | 高且深 |
| 砂锅 | 16-20cm | 厚壁、带盖 |

| 食物类型 | 密度（g/ml） | 备注 |
|---|---:|---|
| 米饭（松散） | 0.6-0.7 | 家常盛饭 |
| 米饭（压实） | 0.8 | 外卖压紧 |
| 面条（熟） | 0.7-0.9 | 含汤水时偏高 |
| 炒饭或炒面 | 0.8-0.9 | 比白饭或白面密实 |
| 粥 | 0.9-1.0 | 接近水 |
| 叶菜（炒或烫） | 0.3-0.5 | 疏松 |
| 根茎类 | 0.8-1.0 | 密实 |
| 豆腐 | 0.9-1.0 | 接近水 |
| 猪肉（块或片） | 0.8-1.0 | 密实 |
| 鸡肉（块） | 0.7-0.9 | 带骨时偏低 |
| 鱼肉 | 0.8-0.9 | 去骨 |
| 虾仁 | 0.7-0.8 | 有间隙 |
| 鸡蛋（炒） | 0.6-0.7 | 蓬松 |
| 水饺或馄饨 | 0.7-0.8 | 有间隙 |
| 包子或馒头 | 0.3-0.4 | 蓬松面食 |
| 饼类 | 0.7-0.9 | 较密实 |
| 坚果 | 0.5-0.7 | 有间隙 |
| 汤类 | 约 1.0 | 接近水 |

### 第二级：已知尺寸锚定

照片中存在尺寸相对固定的食物或常见物体时，用它校准其他食物：

| 锚定物 | 标准尺寸或重量 |
|---|---|
| 鸡蛋 | 长约 5.5cm，去壳约 50g |
| 饺子 | 长约 7-8cm，约 25-30g/个 |
| 标准馒头 | 直径约 8cm，约 80-100g |
| 易拉罐 | 高 12.3cm，直径 6.6cm |
| 矿泉水瓶 | 高 21cm，直径 6.5cm |

不要要求用户为了估算额外摆放参照物；只使用照片中已经出现的锚点。

### 第三级：标准份量兜底

容器和锚点都不可见时，使用标准份量上限作为低置信度兜底：

| 场景 | 默认份量 |
|---|---:|
| 一人份米饭 | 200g |
| 一人份面条（熟） | 350g |
| 餐厅一份炒菜 | 300g |
| 一个肉夹馍或煎饼 | 250g |
| 一根玉米 | 200g（含芯） |
| 一个苹果或梨 | 250g |
| 一根香蕉 | 150g（含皮） |

### 可食用比例折算

带骨、带壳或带皮食物先保存观察总量，再折算可食部分：

| 食物 | 可食用比例 |
|---|---:|
| 带骨鸡（鸡腿或鸡翅） | 0.7 |
| 排骨 | 0.6 |
| 带壳虾 | 0.5 |
| 带壳蟹 | 0.4 |
| 带皮水果（橙或柚） | 0.7 |

不确定时采用合理范围内较高的可食比例，以免低估。按以下方式记录：

```text
quantity.gross_value = 观察总量
quantity.edible_ratio = 可食比例
quantity.value = floor(gross_value * edible_ratio + 0.5)
```

`quantity.value` 是参与热量计算的可食量；兼容 `weight_g` 也使用该值。

### 辅助方法

#### 数量计数法

对可以数个数的食物：

1. 数清个数；
2. 回忆或查询单个标准可食重量；
3. 使用 `个数 × 单个可食重量` 得到兼容重量；
4. 在权威数量中保留 piece，在兼容字段中保存估算重量。

常见锚点包括鸡蛋去壳约 50g、鹌鹑蛋去壳约 8g、馄饨约 25-35g/个。数量计数通常比纯体积估算更可靠。

#### 面积厚度法

对盘中平铺的切片肉或炒菜：

1. 参照盘子估算覆盖面积；
2. 估算平均厚度，例如一层叶菜约 1-2cm、肉片堆约 2-3cm；
3. 使用 `面积 × 厚度` 得到体积；
4. 使用 `体积 × 密度` 得到重量。

#### 包装直接读取

包装上有净含量时直接使用。读取 `g` 或 `ml` 单位，不再用视觉估算覆盖它。液体为兼容旧字段时可以数值上按 `1ml = 1g` 投影，但热量仍按每 100ml 或整份数据计算。

#### 份量比例法

当前对话中出现过同一或高度相似食物时：

1. 找到之前的份量与热量依据；
2. 对比本次盛装量；
3. 按视觉比例缩放份量；
4. 保持相同能量密度，除非做法或规格已变化。

### 同一容器中的多种食物

1. 先估算容器内食物总体积；
2. 目测每种食物的体积或重量比例，注意堆叠；
3. 按各自密度计算重量。

根据是否经过同一烹饪过程区分处理：分别烹饪后装在一起的米饭、肉菜、蔬菜按独立食物计算；同一锅产出的混合菜按复合菜品处理。

## 第三阶段：热量计算

### 固体食物常规路径

对无法直接读取整份热量的固体，使用：

```text
热量(kcal) = 可食用重量(g) × 成品热量(kcal/100g) ÷ 100
```

优先使用成品每 100g 数据。成品数据已经包含做法、调味和用油的平均影响，不要再施加烹饪修正。

### 常规数据获取流程

包装标签和规格明确的品牌 SKU 已在识别阶段优先处理；其余食物执行：

```text
查个人索引
  ↓ 未命中
回忆可靠成品数据或训练知识
  ↓ 不确信 / 高热量 / 不常见
Web 搜索“菜品名 每100g 热量”
  ↓ 没找到
更换同义词或近义菜名再搜
  ↓ 仍没找到
拆为原料，逐项查原料数据，合计后只加一次烹饪修正
  ↓
可选：搜索“一份 热量”仅用于合理性校验
```

遵守以下规则：

- 成品数据直接乘实际重量，不再修正；
- 普通“一份”数据只用于校验，因为份量定义不明确；
- 规格明确的品牌 SKU 是例外，可以直接使用整份热量；
- 中国营养标签常用 kJ，使用 `kcal = kJ ÷ 4.184` 转换。

### 三档烹饪修正

只有找不到成品数据、必须使用原料数据时才应用：

| 档位 | 烹饪方式 | 统一修正 |
|---|---|---:|
| 低油 | 水煮、蒸、烫、白灼、凉拌 | ×1.0 |
| 中油 | 炒、红烧、卤、糖醋、烤、烘 | ×1.3 |
| 高油 | 煎、油炸、干炸、干煸、干锅、拔丝 | ×1.8 |

档位不确定时上提一档。复合菜拆分时，对所有原料热量之和只应用一次修正，不要逐组件重复应用。

### 汤类

不要用总重量直接乘普通成品密度，因为大部分重量是水：

1. 识别肉、蛋、豆腐、蔬菜等固体配料；
2. 分别估算每种固体配料的重量；
3. 查各配料的原料每 100g 热量；水煮或炖使用 ×1.0，不额外修正；
4. 估算汤水容量；清汤按 5-15 kcal/100ml，浓汤或奶汤按 20-40 kcal/100ml；
5. 把固体热量与汤水热量相加。

### 复合菜品

多种食材经过同一烹饪过程时：

- **整体法优先**：找到该菜品可靠的成品每 100g 数据后，直接乘可食重量。
- **拆分法兜底**：整体数据找不到时，统一使用原料路径：
  1. 估算总重量和各食材重量比例；
  2. 所有组件都查原料或生食每 100g 数据；
  3. 分别计算原料热量并求和；
  4. 按整道菜做法对总和施加一次烹饪修正。

不要对各组件分别查成品数据再相加。每份成品数据都可能包含独立用油量，会让同一锅菜重复计算油脂。

### 额外蘸料

只计算照片中明确可见的蘸碟，不猜测看不到的调味：

| 蘸料 | 热量/份 |
|---|---:|
| 酱油加醋 | 可忽略 |
| 麻酱或花生酱 | 80-100 kcal |
| 辣椒油 | 40-60 kcal |
| 沙拉酱 | 50-80 kcal |

范围无法收窄时采用上限。

### 饮品独立流程

饮品不要套用固体的每 100g 路径。先选择分支：

```text
识别饮品
  ↓
是否为品牌与规格明确的产品？
  ├─ 是：使用官方或包装 SKU 整份数据
  └─ 否：是否能拆为基底和添加物？
       ├─ 是：执行容量 + 基底 + 添加物流程
       └─ 否：搜索饮品成品热量，按同类合理高值估算
```

基底拆解流程适用于自制咖啡、便利店现调饮品或配料可见的鲜榨果汁等。商业预混饮品优先使用包装、品牌或品类成品数据。

```text
第一步：识别容器并确定总容量(ml)
第二步：识别基底并确定基底能量密度(kcal/100ml)
第三步：识别并逐项加算添加物
第四步：总热量 = 容量 × 基底能量密度 ÷ 100 + 添加物热量
```

#### 容器容量参照

|---|---:|

| 咖啡中杯 | 360ml |

|---|---:|

| 脱脂牛奶 | 约 35 |
| 无糖豆浆 | 约 30 |
| 鲜榨果汁 | 约 55 |
| 碳酸饮料 | 约 40 |
| 原味酸奶 | 约 70 |
| 啤酒 | 约 35 |
| 50 度白酒 | 约 300 |
| 红酒 | 约 85 |

#### 常见添加物

| 添加物 | 热量/份 |
|---|---:|
| 糖浆 1 泵 | 约 20 kcal |
| 奶盖 | 约 150 kcal |
| 珍珠（标准份） | 约 150 kcal |
| 椰果 | 约 50 kcal |
| 芋圆 | 约 100 kcal |
| 炼乳 | 约 60 kcal |
| 奶油顶 | 约 100 kcal |

糖度未知时按全糖计算，不追问；杯型未知时按大杯。珍珠、奶盖等高热量加料不确定时必须追问。

基底表按无糖或原味理解。点单类饮品按全糖计算时，中杯额外加 60 kcal，大杯额外加 80 kcal；半糖取全糖额外值的一半。碳酸饮料、瓶装果汁等预调饮品的糖已经包含在成品或基底数据中，不要重复加糖。

### 最终取整

保留未取整中间值完成单项计算和合理性检查，再把最终 item 热量取为约 5 或 10 kcal 的整数展示值。记录中只保存该最终 `item.calories`；餐次和全天 totals 对已经保存的 item 值求和，不要从未取整中间值重新派生。

## 第四阶段：一致性与合理性校验

输出前完成以下检查。

### 校验一：跨餐次一致性

回顾当前对话和个人索引中是否出现过同一或高度相似食物：

- 做法和能量依据相同时，新估值应与旧估值按份量成比例；
- 例如之前 200g 对应 250 kcal，本次相同食物约 80g 时应接近 100 kcal，而不是仍使用整份 250 kcal；
- 做法、规格或来源变化时，说明为什么不沿用原能量密度。

### 校验二：单餐总量

用以下范围做错误检查，不把它们当成必须压入的目标：

- 简单早餐：300-600 kcal；
- 正式午餐或晚餐：500-1000 kcal；
- 丰盛午餐或晚餐：800-1300 kcal；
- 加餐或零食：50-300 kcal。

明显超出时重新检查重量、能量单位、重复计数和用油，不要只为落入范围而修改正确结果。

### 校验三：单项合理性

使用以下常见范围发现数量级错误：

- 一碗普通米饭：200-300 kcal，超过 300 时确认是否为特别大碗；
- 一份普通炒蔬菜：60-150 kcal，超过 150 时确认份量或用油；
- 一碗汤：50-350 kcal，结合固体配料判断；
- 一个水煮蛋：约 70 kcal，不应大幅波动。

单项明显异常时，检查份量和每 100g、每 100ml 或整份能量依据是否错配。

特别留意多个“取高”相乘造成的过度高估，例如容器容量上限 × 密度上限 × 能量密度上限。重新查看照片，把实际可确认的环节收窄，只对仍不确定的环节保留高值。

### 校验四：结构与重复

逐项确认：

1. kcal 与 kJ 换算正确；g、ml、piece、serving 没有混用公式；
2. 同一组食物的多角度照片没有重复计数；
3. 复合菜没有把共享用油算多次；
4. 饮品预调基底与额外糖没有重复计算；
5. 带骨、壳、皮食物使用可食量计算，而不是观察总量；
6. 所有 totals 都来自已保存的 item calories。

## 第五阶段：置信度与沟通

### 判断置信度

**高置信度**：

- 营养标签清晰可读；
- 品牌、产品和规格明确，且有官方 SKU 数据；
- 可数的标准食物；
- 常见餐具盛装的常见食物，份量依据清楚。

直接给约数，例如“约 230 kcal”。

**中置信度**：

- 食物可识别，但份量仍有约 ±20% 的不确定性；
- 做法基本明确，但用油量不确定；
- 能量数据可靠，照片份量只能估算。

仍给单一约数，并准备接受用户纠正。

**低置信度**：

- 食物种类不完全确定；
- 被遮挡或照片模糊；
- 不常见菜品且数据只能近似；
- 只能使用标准份量兜底。

采用合理高值，并简短标注“该项不确定，已按较高值估算”。只有追问矩阵命中“必须问”时才打断用户。

### 处理用户纠正

区分两类纠正：

1. **食物种类纠正**：重新查该食物的能量依据并重算；
2. **份量纠正**：保持原能量密度不变，按新份量缩放。

做法、糖度或加料变化时重新选择计算分支。纠正后简短确认；热量变化小于 5% 时可以说明“热量基本不变”。记录覆盖与 ID 定位规则由 `record-schema.md` 和主 `SKILL.md` 处理。

### 避免伪精确

照片估算通常存在约 ±15-20% 的正常误差。不要输出类似 237 kcal 的伪精确值；使用整 5 或整 10 的约数，例如约 235、240 或 230 kcal。首次记录时提示一次估算误差即可，不要反复添加免责声明。

## 推理检查清单

每次估算时在内部检查：

```text
□ 图片去重：同一组食物的多个角度只计了一次吗？
□ 个人索引：先查了 food-calorie-index.md 吗？规格确实一致吗？
□ 食物识别：(食物、做法、依据、置信度) 完整吗？
□ 追问决策：必须确认的问题是否一次问完？
□ 份量推导：固体重量、饮品容量或数量用了哪种方法？
□ 可食比例：带骨、壳、皮项目保存了总量并使用可食量计算吗？
□ 热量数据：使用的是成品、整份 SKU 还是原料数据？
□ 成品数据：直接使用，没有额外烹饪修正吗？
□ 原料数据：只在最后手段使用，并且整道菜只修正一次吗？
□ 汤与饮品：走了各自的独立流程吗？
□ 蘸料：只计算了照片中明确出现的蘸料吗？
□ 交叉验证：高热量或不常见食物搜索验证了吗？
□ 一致性：同类食物的份量与热量比例合理吗？
□ 合理性：单项和单餐有没有数量级错误？
□ 重复计算：照片、共享用油、预调糖或加料有没有重复？
□ 取整与 totals：先保存 item 展示值，再求和了吗？
□ 索引更新：只有可靠、可复用的数据才写入了吗？
```

不要把完整推理过程展示给用户，但确保每个最终数字都能由这些步骤支撑。
