# 个人食物热量索引

本文件保存用户反复食用、且已经可靠核验的成品能量密度或明确品牌 SKU。估算前先查询本索引；未命中时继续执行 `estimation-method.md` 的常规数据获取流程。

当前索引为空。不要把下方表头当成内置食物数据库，也不要自行补入示例值。

## 查询规则

1. 先标准化食物名称，保留会影响能量值的做法、口味、品牌、杯型或规格。
2. 只把同一或高度相似的食物视为命中；不要把原料值当成成品值，也不要把不同做法互相替代。
3. 按 `能量单位` 计算：
   - `kcal/100g`：用于固体成品重量；
   - `kcal/100ml`：用于可复用的饮品能量密度；
   - `kcal/serving`：只用于规格明确、份量固定的品牌 SKU。
4. 命中后仍要核对照片或用户描述中的规格；规格不一致时视为未命中。
5. 索引未命中时，不要根据相似名称臆造条目。

## 写入规则

只写入可复用且来源足够可靠的数据：

- 接受清晰的包装营养标签；
- 接受品牌官方公布且规格明确的 SKU；
- 接受来源可靠、定义清楚的成品每 100g 或每 100ml 数据；
- 标注来源类型、来源说明与核验日期；
- 同一标准化食物键只保留一条，修正时更新原条目；
- 不要写入某一餐的实际份量；
- 不要自动写入低置信度照片推断、仅由标准份量兜底得到的结果，或原料拆解产生的整道菜估值。

索引更新是估算后的辅助步骤，不是本次计算的前置条件。若 skill 安装目录只读或写入失败，继续返回本次估算，并明确不要把该条目报告为“已保存”；不得为了更新索引而改写权限、复制整个 skill 或阻塞用户请求。

高热量或少见食物经训练知识得到数据时，先按 `estimation-method.md` 完成交叉验证，再决定是否写入。

## 字段说明

| 字段 | 说明 |
|---|---|
| 标准化食物键 | 含必要做法、品牌、口味、杯型或规格的唯一名称 |
| 能量值 | 与能量单位配套的非负数值 |
| 能量单位 | `kcal/100g`、`kcal/100ml` 或 `kcal/serving` |
| 固定规格 | `kcal/serving` 条目的容量、重量、杯型或版本；其他条目可留空 |
| 来源类型 | `package_label`、`brand_official`、`food_composition_table` 或 `web` |
| 来源说明 | 可复核的标签、机构、品牌页面或资料名称 |
| 核验日期 | `YYYY-MM-DD` |
| 备注 | 别名、适用边界或修订原因；可留空 |
