# 食物热量估算与记录

## 按请求选择操作

| 模式 | 典型意图 | 状态行为 |
|---|---|---|
| `estimate` | 询问本次食物热量 | 只估算，不记录 |
| `record` | 明确记录、打卡或说明“这是我的早餐/午餐/晚餐” | 更新当前对话状态 |
| `correct` | 修改既有条目的食物、份量、做法、糖度或加料 | 覆盖目标条目 |
| `status` | 查询某日或当前累计 | 只读取状态 |
| `summary` | 明确要求每日汇总或出长图 | 生成兼容旧版字段的 JSON 并出图 |

此技能仅处理热量估算和当前对话中的饮食记录。组合请求按用户指定的顺序执行。顺序未指定且查询或汇总依赖本次记录或纠正时，先更新，再读取更新后的数据。

查询与汇总优先使用用户为该操作指定的日期。若未指定且指向同一请求中记录或纠正的餐次，沿用该餐次的日期。仍无日期线索时使用当地当天。需要在请求涉及的多个日期中确定一个、且上下文无法确定时，先确认目标日期，继续处理独立操作。

## 按需读取资料

复用当前上下文中仍适用的资料。新估算或变更热量依据时，查阅 [估算方法](references/estimation-method.md#核心原则) 的核心原则及适用的识别、份量、计算和校验章节，并按其中的优先顺序查 [个人索引](references/food-calorie-index.md#查询规则)。只改份量且原能量依据仍适用时，直接用原依据重算。

记录和纠正参照 [字段规则](references/record-schema.md#字段规则)。新增或修改枚举、数量或旧版重量时，查阅适用的 [枚举定义](references/record-schema.md#枚举) 和 [数量投影规则](references/record-schema.md#数量与旧重量投影)。查询使用已存储热量，必要时查阅 [合计规则](references/record-schema.md#合计规则)。生成长图时查阅完整的 [JSON 规范](references/record-schema.md)。

## 估算与回显

1. 接受一张或多张照片，也接受文字描述。同一组食物的多个角度只计一次，使用较清晰的角度补充识别。
2. 优先读取品牌、包装、容量和营养标签。接着确认食物及做法，先量化份量，再选热量依据和计算分支。按 [追问决策矩阵](references/estimation-method.md#追问决策矩阵) 合并必须确认的问题，同时完成可独立判断的项目。可保守估算时，按矩阵取值，并在影响结果时注明采用的假设。
3. [校验单位、算术和重复计数](references/estimation-method.md#第四阶段一致性与合理性校验)，再按约 5 或 10 kcal 取整各项并求和。展示食物名称、数量、单位、热量和本次合计，简述[低置信度项](references/estimation-method.md#判断置信度)的依据。首次记录时说明照片估算的正常误差。
4. 按 [索引写入规则](references/food-calorie-index.md#写入规则) 保存可靠、可复用的能量依据。索引不可写时继续完成本次估算，只在实际写入成功时报告已保存。

## 记录、纠正与查询

优先使用用户指定的日期和餐次。日期默认使用当地当天（`YYYY-MM-DD`），餐次可结合对话和当地时间推断。记录时按日期、餐次和条目维护状态，为新餐次和食物分配稳定的 `meal.id` 和 `item.id`。把实际可访问的图片路径按原顺序归入对应餐次。

同日同类餐次明显是补充时，向原餐追加新条目。同一食物的补充照片只补充证据。用户明确表示是另一次同类餐次时，新建餐次；无法确定归属时先确认。记录完成后回显餐次、本餐合计和当日累计。

纠正时根据用户指定的日期、餐次、序号或最近一次回显定位条目。结合稳定的 `item.id` 和范围内的唯一候选确认目标；仍有多个候选时请用户指定。只改份量时按原能量依据重算，变更食物、做法、糖度或加料时重新选择计算分支。覆盖原条目并保留 ID，用已取整的 `item.calories` 重算餐次和全天合计。此前的汇总图随之过期，等用户再次要求时重生成。

查询时按所问日期或餐次直接汇总 `item.calories`。没有可用记录时如实说明。每日记录只在当前对话维护，只在出图时写入临时 JSON。

## 生成每日汇总

1. 按请求中的日期规则选择目标日期。该日没有记录时直接说明。
2. 按 JSON 规范校验并写入临时 `schema_version: "2.0"` JSON，保留全部旧版必需字段及餐次、条目和各餐图片的原始顺序。
3. 用汇总脚本生成 PNG。

```bash
python <skill目录>/scripts/generate_summary.py --data <临时JSON路径> --output <可访问的输出路径>/daily_summary.png
```

4. 确认本次生成的 PNG 可打开，再将图交给用户。校验失败时根据实际错误修正能从对话恢复的数据后重试，保留用户原记录。缺少 Pillow 时说明依赖，禁止自动安装或修改系统 Python。
